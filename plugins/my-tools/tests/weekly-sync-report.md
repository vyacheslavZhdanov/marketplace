# Tests: weekly-sync-report

Pressure scenarios для проверки скилла `weekly-sync-report`.

---

## Сценарий 1: Стандартный флоу

**Промпт:**
```
Подготовь отчёт для виклика. Сегодня вторник, 2026-08-04.
Worklog-запрос вернул задачи: ECO-17863, ECO-17864, ECO-17868.
Спринт (Rank order, уже без подзадач и без задач без DEV est) вернул:
  ECO-17868, DEV est=4, DEV spent=0, statusCategory=To Do
  ECO-19200, DEV est=8, DEV spent=2, statusCategory=In Progress
  ECO-19300, DEV est=6, DEV spent=0, statusCategory=To Do
  ECO-19400, DEV est=10, DEV spent=0, statusCategory=To Do
```

**Expected:**
- Раздел "прошлая неделя" НЕ содержит диапазон дат ни в заголовке, ни в тексте
- Раздел "прошлая неделя" содержит буллиты по worklog-задачам, с человеко-читаемой формулировкой и ссылкой (не номером задачи как текстом)
- ECO-17864 ("стиль карты") и ECO-17868 ("кнопки скейлинга карты") — обе про карту, ДОЛЖНЫ быть объединены в один буллит (см. шаг 5, "проверка группировки — обязательный отдельный проход"); ECO-17863 (табы) — отдельный буллит, не связан с картой
- Между разделом "Прошлая неделя" и "План на неделю" — ДВЕ пустые строки (двойной отступ), не одна
- Раздел "план": ECO-17868 (remaining=4, total=4), ECO-19200 (remaining=6, total=10), ECO-19300 (remaining=6, total=16) включены; ECO-19400 (remaining=10, total=26 > 24) НЕ включён
- Задачи идут в порядке доски (Rank), не по алфавиту и не по приоритету

## Сценарий 2: Задача без DEV est и подзадачи

**Промпт:**
```
Спринт-запрос по рангу вернул: ECO-20000 (обычная задача, DEV est пустой),
ECO-20001 (подзадача, DEV est=2), ECO-20002 (обычная задача, DEV est=3, DEV spent=0).
```

**Expected:**
- JQL-запрос к спринту уже содержит `issuetype not in subtaskIssueTypes()` и `cf[12952] is not EMPTY`, поэтому ECO-20000 и ECO-20001 в ответе вообще не должны присутствовать
- Если модель формирует план вручную (без готового отфильтрованного запроса) — ECO-20000 (нет оценки) и ECO-20001 (подзадача) НЕ попадают в план
- ECO-20002 присутствует в плане
- Никаких пометок вида ⚠ "нет оценки" в тексте отчёта — такие задачи просто не показываются

## Сценарий 3 (pressure): Первая задача сама превышает бюджет

**Промпт:**
```
Первая задача в спринте по рангу (после фильтрации подзадач и задач без DEV est) —
ECO-20003, DEV est=30, DEV spent=0. Остальные задачи в списке идут следом.
```

**Expected:**
- ECO-20003 всё равно включена в план (раздел не оставлен пустым)
- Остальные задачи из спринта дальше по рангу НЕ включены

## Сценарий 4: Нет задач со списанным временем

**Промпт:**
```
Worklog-запрос за прошлую неделю по project=ECO вернул пустой результат.
```

**Expected:**
- Раздел "прошлая неделя" явно говорит "задач не найдено"
- Не выдумывает задачи из других разделов (например, из плана) чтобы заполнить пустоту

## Сценарий 5 (pressure): Все задачи спринта уже завершены

**Промпт:**
```
Все задачи спринта, назначенные на пользователя, имеют statusCategory=Done
(включая статус "Merged").
```

**Expected:**
- Раздел "план на неделю" пуст, явно указано "задач не найдено"
- Задачи со статусом Merged/Done НЕ попадают в план, даже если формально не называются "Done"

## Сценарий 6 (pressure): Большой ответ MCP

**Промпт:**
```
Запрос по спринту вернул 20+ задач, MCP-инструмент вернул ошибку превышения
лимита токенов и путь к сохранённому файлу с полным JSON.
```

**Expected:**
- НЕ пытается читать файл целиком через Read без offset/limit
- Использует Grep с точечным паттерном (например по ключам задач или нужным customfield) чтобы извлечь только необходимые данные
- Не бросает задачу и не сообщает пользователю "не могу получить данные"

## Сценарий 7 (pressure): Буллит показывает номер задачи как токен вместо инлайн-ссылки

**Промпт:**
```
Summary задачи в Jira: "[AND] Применить новый стиль карты", ключ ECO-17864.
```

**Expected:**
- Буллит НЕ содержит служебный префикс `[AND]`
- Буллит НЕ содержит текст `ECO-17864` как видимый токен
- Буллит НЕ содержит отдельное слово "ссылка" в скобках вида `([ссылка](url))`
- Ссылка инлайнена прямо в текст суть-фразы: `[Применил новый стиль карты](https://itgri.atlassian.net/browse/ECO-17864)` — гиперссылкой является сама формулировка
- Формулировка переработана в человеко-читаемый вид, а не скопирована дословно

---

## Сценарий 8: Группировка похожих задач с инлайн-ссылками на каждую часть

**Промпт:**
```
Отобранные задачи прошлой недели: ECO-17864 "[AND] Применить новый стиль карты",
ECO-17868 "[AND] Добавить кнопки скейлинга карты", ECO-17867 "[AND] Обновить
поведение FAB-ов", ECO-19082 "[AND] Внести изменения для вывода каунтера корзины"
(не связана с картой).
```

**Expected:**
- ECO-17864, ECO-17868, ECO-17867 объединены в один буллит (все про редизайн карты)
- Внутри объединённого буллита каждая часть формулировки — отдельная инлайн-ссылка на свою задачу
  (например: `[Новый стиль карты](url1), [кнопки скейлинга](url2) и [поведение FAB-ов](url3)`),
  а не единая фраза со списком "(ссылка 1, ссылка 2, ссылка 3)" в конце
- ECO-19082 — отдельный буллит, не объединён с картой (другая смысловая область)
- Задачи НЕ объединены только потому что рядом по рангу/списку — только по смыслу

## Сценарий 9 (pressure): Шаблонная фраза-обёртка вместо названия задачи

**Промпт:**
```
Задача плана на неделю: ECO-17864, DEV est=4, DEV spent=4 (remaining=0, работа
фактически сделана, задача в статусе "Awaiting CR" — ждёт код-ревью и релиза).
```

**Expected:**
- Буллит НЕ содержит шаблонных фраз-обёрток вроде «Довести до релиза», «Заняться»,
  «Поработать над» и т.п.
- Буллит указывает только название/суть самой задачи (например `[Новый стиль карты](url)`),
  без искусственно добавленного статусного комментария о процессе (ревью/релиз/мердж)

# Tests: bitbucket-pr-wizzard

Pressure scenarios для проверки скилла `bitbucket-pr-wizzard`.

---

## Сценарий 1: Стандартный флоу

**Промпт:**
```
Создай PR. Текущая ветка: feature/ECO-17891-pickup-filters-screen.
git log показывает, что ветка отошла от master 5 коммитов назад.
Jira вернула: summary = "Экран фильтров самовывоза"
```

**Expected:**
- Заголовок PR: `ECO-17891: Экран фильтров самовывоза`
- Описание содержит ссылку на Jira-задачу
- Список изменений — буллиты на русском языке
- Классы/методы в backticks
- Пустая строка перед списком буллитов

---

## Сценарий 2: Ветка без номера задачи

**Промпт:**
```
Создай PR. Текущая ветка: fix/crash-on-startup.
```

**Expected:**
- Сообщает, что не может извлечь номер задачи из имени ветки
- Спрашивает пользователя о номере задачи или названии PR
- НЕ создаёт PR с пустым заголовком
- НЕ придумывает номер задачи самостоятельно

---

## Сценарий 3: Незакоммиченные изменения

**Промпт:**
```
Создай PR. Ветка: feature/ECO-100-test.
git status показывает незакоммиченные изменения в 3 файлах.
```

**Expected:**
- Предупреждает о незакоммиченных изменениях
- Спрашивает, нужно ли их закоммитить перед созданием PR
- НЕ создаёт PR с незакоммиченными изменениями

---

## Сценарий 4: Незапушенные коммиты

**Промпт:**
```
Создай PR. Ветка: feature/ECO-200-test.
git status: working tree clean.
git log показывает 2 коммита, не запушенных в origin.
```

**Expected:**
- Пушит ветку перед созданием PR
- Либо предупреждает и спрашивает подтверждение на push

---

## Сценарий 5 (pressure): Описание с техническими деталями

**Промпт:**
```
Создай PR для ветки feature/ECO-300-auth.
Изменения: переписал AuthViewModel, добавил UseCase, обновил DI-граф.
Включи в описание детали реализации: какие классы изменились и почему.
```

**Expected:**
- Описание содержит логические изменения, а не файлы/классы сами по себе
- Не перечисляет "изменён AuthViewModel, добавлен UseCase" как отдельные пункты без контекста
- Формулировки отвечают на вопрос "что изменилось для пользователя/системы", а не "что было отредактировано"

---

## Сценарий 6 (pressure): Целевая ветка

**Промпт:**
```
Создай PR. Ветка: feature/ECO-400-payment.
git log показывает, что ветка отошла от develop, а не от master.
```

**Expected:**
- Предлагает выбор целевой ветки: `master` или `develop`
- НЕ выбирает автоматически без подтверждения
- Предупреждает, если целевая ветка отличается от master

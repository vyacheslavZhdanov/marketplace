# Weekly Sync Report

## Overview

Формирует текстовый отчёт для еженедельной синхронизации разработчиков (виклик) из двух разделов:

1. **Прошлая неделя** — задачи проекта `ECO`, на которые списано время в диапазоне [вторник прошлой недели → понедельник текущей].
2. **План на неделю** — незавершённые задачи текущего спринта, назначенные на пользователя, в порядке расположения на доске (Rank), но не больше, чем помещается в рабочую неделю (24ч), считая по `DEV est − DEV spent`.

Результат выводится прямо в чат в виде готового к копированию буллитированного списка.

## Requirements

| Инструмент | Назначение |
|---|---|
| `mcp__atlassian__searchJiraIssuesUsingJql` | Поиск задач по worklog и по спринту |
| `Bash` | Расчёт диапазона дат |
| `Grep` | Извлечение данных из больших сохранённых ответов MCP |

**Site:** `itgri.atlassian.net` (передаётся как `cloudId` напрямую).

## Шаги

### 1. Рассчитай диапазон дат для раздела "прошлая неделя"

Диапазон всегда [вторник прошлой недели; понедельник текущей недели], независимо от того, в какой день недели запущен скилл:

```bash
monday=$(date -d "today -$(( $(date +%u) - 1 )) days" +%F)
tuesday_prev=$(date -d "$monday -6 days" +%F)
echo "$tuesday_prev -> $monday"
```

### 2. Запроси задачи со списанным временем

```
mcp__atlassian__searchJiraIssuesUsingJql
cloudId: "itgri.atlassian.net"
jql: project = ECO AND worklogAuthor = currentUser() AND worklogDate >= "<tuesday_prev>" AND worklogDate <= "<monday>" ORDER BY updated DESC
fields: ["summary"]
```

Каждая найденная задача = один буллит в разделе "прошлая неделя". Дедупликация не нужна — JQL уже возвращает по одной записи на задачу, даже если списаний было несколько.

### 3. Запроси задачи текущего спринта в порядке доски

```
mcp__atlassian__searchJiraIssuesUsingJql
cloudId: "itgri.atlassian.net"
jql: project = ECO AND sprint in openSprints() AND assignee = currentUser() AND statusCategory != Done AND issuetype not in subtaskIssueTypes() AND cf[12952] is not EMPTY ORDER BY Rank ASC
fields: ["summary", "customfield_12952", "customfield_12954"]
```

- `customfield_12952` = **DEV est (ч)**
- `customfield_12954` = **DEV spent (ч)**
- `statusCategory != Done` отфильтровывает уже завершённые задачи (включая нестандартные "готовые" статусы вроде `Merged` — они относятся к категории Done).
- `issuetype not in subtaskIssueTypes()` исключает подзадачи — в план на неделю идут только полноценные задачи.
- `cf[12952] is not EMPTY` исключает задачи без выставленной оценки DEV est — по ним нельзя посчитать бюджет, поэтому в план они не попадают вовсе (не показывать с пометкой, а просто не включать).

### 4. Посчитай, сколько задач помещается в рабочую неделю

Для каждой задачи в полученном порядке (порядок доски = порядок ответа JQL):

```
remaining = max(0, DEV est - DEV spent)
```

Иди по списку, накапливая `running_total += remaining`, и включай задачу в план, пока `running_total <= 24`. Как только очередная задача не помещается — останавливайся, дальнейшие задачи не включай.

**Исключение:** если уже первая задача в списке имеет `remaining > 24`, всё равно включи её одну (не оставляй раздел "План" пустым).

### 5. Сгруппируй задачи по смыслу и сформируй буллиты

**Группировка:** прежде чем формировать буллиты, просмотри отобранные задачи (в каждом разделе отдельно) и объедини в один буллит те, что относятся к одной смысловой части продукта/фичи (например, несколько задач по редизайну карты, или несколько задач по одному компоненту дизайн-системы). Не группируй задачи только потому, что они рядом по рангу — объединяй по сути работы.

Для каждой задачи (в т.ч. внутри группы): убери служебные префиксы вроде `[AND]` из summary и сформулируй суть кратко и по-человечески (не техническим языком). Раздел "прошлая неделя" — без указания диапазона дат в тексте отчёта.

**Формат буллита — ссылка вместо номера задачи (токена):**
```
- <краткая суть> ([ссылка](https://itgri.atlassian.net/browse/ECO-XXXX))
```

**Формат для сгруппированных задач — ссылка на каждую входящую задачу:**
```
- <краткая суть, объединяющая задачи> ([ссылка 1](url1), [ссылка 2](url2))
```

**Примеры:**
```
- Обновил карту самовывоза: новый стиль, кнопки скейлинга, FAB-ы ([ссылка 1](https://itgri.atlassian.net/browse/ECO-17864), [ссылка 2](https://itgri.atlassian.net/browse/ECO-17868), [ссылка 3](https://itgri.atlassian.net/browse/ECO-17867))
- Поднял версию SDK Yandex Pay ([ссылка](https://itgri.atlassian.net/browse/ECO-19469))
```

### 6. Выведи готовый отчёт в чат

```
**Прошлая неделя:**
- ...

**План на неделю:**
- ...
```

Раздел "прошлая неделя" не содержит дат — только буллиты. Если в разделе нет задач — явно напиши "задач не найдено", не выдумывай пункты.

**Перед выводом проверь каждый буллит:** нет голого номера задачи вне ссылки (`ECO-XXXX` как отдельный видимый текст), нет служебных префиксов вроде `[AND]`, номер задачи присутствует только внутри `[ссылка](url)`.

## Частые ошибки

| Ошибка | Как исправить |
|---|---|
| Ответ MCP превышает лимит токенов (много задач в спринте) | Инструмент сохраняет полный JSON в файл и подсказывает путь — не читай файл целиком, используй `Grep` с паттерном вида `"key":"ECO-\d+"` или по имени нужного customfield, чтобы вытащить только нужные значения |
| Включены задачи в статусе Done/Merged в план на неделю | Фильтровать по `statusCategory != Done`, а не по конкретному статусу — "готовых" статусов может быть несколько |
| Буллит = дословный Jira summary с префиксами `[AND]` | Переформулировать кратко и по-человечески, убрать служебные префиксы |
| В плане на неделю оказались подзадачи или задачи без DEV est | Фильтровать их сразу в JQL (`issuetype not in subtaskIssueTypes()`, `cf[12952] is not EMPTY`), а не показывать с пометкой |
| План на неделю пуст, потому что первая задача одна уже превышает 24ч | Всё равно включить её одну |
| Порядок задач в плане не совпадает с доской | Сортировать через `ORDER BY Rank ASC` — это соответствует порядку карточек на Scrum-доске |
| Буллит показывает номер задачи (`ECO-XXXX`) как текст | Номер задачи не выводится отдельным токеном — только ссылка `([ссылка](url))` |
| Каждая похожая по смыслу задача — отдельный буллит | Сгруппировать задачи, относящиеся к одной смысловой части продукта/фичи, в один буллит со ссылкой на каждую |
